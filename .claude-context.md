# Project Context — ARS Download Manager for Chrome

## Overview
Chrome MV3 extension that limits the speed of already-running Chrome downloads without cancelling/restarting them. Full requirements: `docs/PRD.md`. User docs: `README.md`.

## Technical Stack
- Plain JS ES modules, no build step, no runtime dependencies. Chrome 116+.
- Permissions: `downloads`, `storage`, `alarms` (alarms = 30 s watchdog that restarts the tick loop).
- `background.js` (service worker) → applies decisions from pure `lib/throttle.js` (`planTick`).
- `lib/units.js` (units/format), `lib/state.js` (settings in `storage.local`, our-paused ids in `storage.session`).
- Popup (600×580, download-manager layout since v0.27.0): toolbar (+ link download, ▶, ⏸, 🗑 remove-from-list, 📁), search, tabs (`lib/categories.js` TABS), full history list (200 newest, all states), status bar (🐌 = limiter on/off, ↓ instant + avg speed, ˄ = settings panel). Talks to the SW via `chrome.runtime.sendMessage` (`getState`, `setSettings`, `setPerFile`, `control` {op: pause|resume|cancel|retry|erase, ids?}, `show` {id?}, `download` {url}).
- i18n: `_locales/en` (default) + `_locales/tr`; popup uses `data-i18n*` attributes.
- Tests: `npm test` (node:test + Chrome-behaviour simulator), `npm run test:e2e` (Playwright, `channel: 'chromium'` — headless shell can't load extensions).

## Key Rules
- Throttling = token bucket + `chrome.downloads.pause/resume` (PRD). Keep `lib/throttle.js` free of `chrome.*` so it stays unit-testable.
- Never resume a download the user paused: anything paused but not in `engine.ourPaused` is the user's. Popup pause/resume removes the id from `ourPaused`.
- Pauses are capped at `MAX_PAUSE_S` (15 s) to keep connections alive; debt beyond that is forgiven (documented limitation).
- Sequential mode: queued downloads never drop to 0 — "snail" rate; snail usage is subtracted from the head's budget.
- Measured Chrome facts (do not re-learn): `bytesReceived` published ~every 500 ms only while running (timer restarts on resume; runs < 500 ms report nothing); after pause the sender fills several MB of buffers; every resume drains them. ⇒ Predictive/short run windows do NOT work (tried, broke accounting). Keep reactive pausing.
- Displayed speed = 20 s average (covers a full snail cycle). Summary also shows total instant speed (`totalInstant`, 2 s window — bursty by nature, labelled Anlık/Now next to ort./avg). 2 s window also detects server-limited downloads.
- Popup CSS: `select option` needs explicit bg/colour (native list is white in dark mode). ETA text is localized via `etaHours/etaMinutes/etaSeconds` messages.
- UI strings always in both locales.
- In the list, `paused` means paused by the user only (SW sends `paused: role === 'userPaused'`); the limiter's own pauses show as a running, limited download.
- "Remove" (erase) never deletes files from disk. No upload speed (Chrome downloads don't upload); no thumbnails (API has none) → file-type labels instead.
- UI tests: Playwright renames downloads to GUIDs; send CDP `Browser.setDownloadBehavior {behavior:'allow'}` to keep real names.
- Releases: zip name `ARS-Download-Manager-v.<version>.zip` (note the dot after v — user's choice); git tag `v<version>` must equal `manifest.json` version. Push the tag → `.github/workflows/release.yml` tests, builds via `scripts/build-zip.sh`, publishes. Guides point to `/releases/latest`.
